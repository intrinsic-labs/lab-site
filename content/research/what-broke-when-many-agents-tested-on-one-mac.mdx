Our agents share one Mac. On November 11 and 12, with many agent runs on it and load readings near 200 at times, four pieces of shared plumbing broke, each in a different way.

**A failed listing read as an empty one.** When an agent run ends, a sweep kills the processes it left behind. It listed processes with `ps` limited to 3 s. Under load the call timed out, and the sweep treated that as nothing to kill. After its grace period it re-checked only the processes it had already chosen, so a daemon that forked mid-shutdown was never picked up. Now each listing gets 10 s and up to three tries, and when it has targets, it also looks for new ones after the grace period. With this and fixes to the tests themselves, a test file run 320 times, 20 in parallel beside 12 CPU burners, went from 2 failures to 0.

**A passing verify was killed.** Before our automation switches to a new commit, it runs the full test suite. That run had inherited the 5-minute limit meant for a single git call. Healthy runs took 127 to 275 s in November, so under load the limit killed two runs in which no test had failed. The verify now has its own 15-minute budget.

**A shim found itself.** Agents reach GitHub through a `gh` script early on their PATH, which looks up the real `gh` on PATH. It skipped only the shim in its own state directory, so a process with a different one, such as a test run, could take the live shim for the real `gh` and call back in. Two chains reached about 4,000 processes, 86 GB of swap and 1% free disk before they were killed. The lookup now recognises the marker every generated shim carries, and a re-entry variable makes a call that comes back refuse instead of forking. The next day a hook's own wrapper, without the marker, caused the same loop, so a script whose opening lines wrap the CLI's `gh` command is now recognised as a shim too.

**A version probe never returned.** Tests checked whether the Codex CLI was installed by running `codex --version` with no timeout. Twice on November 12 that hung whole test runs for over 30 minutes. The three probes we found now have a 10 s timeout.

## What we'd tell someone doing the same

- Treat a failed listing as a failure, never as an empty result, and look for new targets after the grace period.
- Give a full-suite verify its own time budget, not the per-command default.
- Guard any shim found on PATH against finding itself: recognise it from any state directory, and set a re-entry variable it refuses to run under.
- Time out every version probe.
